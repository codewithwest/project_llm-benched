# v0.3.0 — Dynamic Proxy Target, Request Filters, Provider Editing & Data Retention

## New Features

- **Dynamic Proxy Target** — change the proxy forwarding target at runtime via `POST /api/proxy/target` or by clicking a provider card in the UI; backed by atomic target URL storage
- **Request Filtering** — filter intercepted requests by provider, endpoint/path, and date range (from/to) on the Requests tab
- **Provider Editing** — edit provider name and URL inline via the new edit button on provider cards; backed by `PATCH /api/dashboard/providers/{id}`
- **Filter Options API** — `GET /api/dashboard/filters` returns distinct providers and endpoints to populate filter dropdowns
- **Data Retention** — new `-retention` flag auto-purges benchmark data older than N hours (0 = disable)

## Improvements

- Provider URL validation on add/update: rejects non-`http://`/`https://` schemes with a `400` error
- More accurate token counting: the proxy interceptor now tracks SSE `data:` lines as tokens, using the max of all three counting methods
- `X-Target-Provider` header scheme validation: unsupported schemes are logged and fall through to the default target
- Scheduled benchmarks update their last-run status to `"completed"` on success
- UI layout: proper scroll containment, separate filtered/unfiltered stats, auto-refresh of filtered stats on polling

## Bug Fixes

- Panic recovery (`defer/recover`) added to all background goroutines — benchmark runs, health poller, scheduler, parallel scaling workers — preventing a single panic from crashing the server
- Provider update returns a proper error if the provider ID does not exist
- Cleaner request body handling on read errors

## Chores

- New API routes: `POST /api/proxy/target`, `PATCH /api/dashboard/providers/{id}`, `GET /api/dashboard/filters`
- New CLI flag: `-retention`
- React `ProviderCard` component extracted for reuse
- Added `sync/atomic` and `net/url` imports
